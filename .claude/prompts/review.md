# Review Prompt

このシステムの保守性をレビューしてください。

このプロジェクトは Kotlin + Jetpack Compose の Android ネイティブアプリです。
Flutter / React Native / Web へ変換しないでください。

既存構成は以下を前提にしてください。

- MVVM
- Hilt
- Room
- StateFlow / Flow
- UseCase 層
- Repository 層
- Jetpack Compose
- Navigation Compose
- ローカルファースト
- バックエンド API なし

レビュー対象は、今回変更されたコード、および影響範囲のある周辺コードです。

以下の観点で評価してください。

## 1. 可読性：10点満点

確認観点:

- 変数名は意味が分かりやすいか
- 関数名は処理内容を正しく表しているか
- クラス名・ファイル名・Composable名・ViewModel名に一貫性があるか
- マジックナンバーや意味不明な文字列が散らばっていないか
- 条件分岐が読みやすいか
- 同じ意味の名前が複数使われていないか
- Kotlin / Compose の一般的な書き方から外れていないか

## 2. 構造：10点満点

確認観点:

- 責務分離されているか
- Compose UI に業務ロジックを書きすぎていないか
- ViewModel が UI 状態管理に集中しているか
- Repository が肥大化していないか
- UseCase 層が適切に使われているか
- DAO / Repository / UseCase / ViewModel / UI の依存方向が崩れていないか
- 既存の MVVM / Hilt / Room / StateFlow 構成に沿っているか
- Navigation は既存の Route sealed class を使っているか

## 3. ドキュメント：10点満点

確認観点:

- コメントは不足していないか
- 逆に不要なコメントが多すぎないか
- 複雑な処理に理由が書かれているか
- 一時対応や例外処理に背景説明があるか
- Room Migration など、後から危険になりやすい変更に説明があるか
- README / CLAUDE_SYSTEM_OVERVIEW.md と矛盾していないか

## 4. テスタビリティ：10点満点

確認観点:

- 関数や UseCase 単位でテストしやすいか
- ViewModel の状態遷移をテストしやすいか
- Room / Repository の処理がテストしやすいか
- Compose UI にロジックが入りすぎてテスト困難になっていないか
- CSV / XLSX import の異常系をテストできるか
- QuizSession / クイズ生成 / 結果保存のテストがしやすいか
- Entity 変更時に Migration test を追加しやすいか

## 5. 拡張性：10点満点

確認観点:

- 新しいクイズ形式を追加しやすいか
- 新しい学習モードを追加しやすいか
- カスタム単語・熟語・文章の機能追加に耐えられるか
- Repository / UseCase / ViewModel の変更範囲が予測できるか
- 既存機能への影響を最小限にして拡張できるか
- Room Entity 変更時に破綻しにくいか
- 画面追加時に Navigation が管理しやすいか

## 注意事項

- 仕様外の改善を勝手に実装しないでください。
